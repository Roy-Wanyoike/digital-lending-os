# DIGITAL LENDING OS — COMPLETE PROJECT AUDIT, FEATURE VERIFICATION & ARCHITECTURE PROMPT

You are a **principal software architect, senior full-stack engineer, DevOps engineer, security engineer, QA engineer, database architect, and product auditor**.

You are auditing an existing **Next.js-based Digital Lending Operating System (Digital Lending OS)**.

The platform is intended to become a **multi-tenant SaaS platform for Digital Credit Providers (DCPs)**, initially targeting Kenya/East Africa and eventually supporting global lending businesses.

The platform must allow many different lenders to use the same core software while configuring:

* Branding
* Loan products
* Interest rates
* Fees
* Eligibility requirements
* KYC requirements
* Approval workflows
* Repayment schedules
* Payment providers
* Notification providers
* User roles
* Business rules
* Customer experience
* Domains/subdomains

The objective is:

> **ONE CORE DIGITAL LENDING PLATFORM → MANY CONFIGURABLE LENDING BUSINESSES**

Do NOT assume that a feature is complete merely because a page, component, database table, API route, or button exists.

You must verify that every feature is actually connected end-to-end and works.

# 15. FINANCIAL LEDGER

This is one of the most important parts of the entire platform.

Do NOT implement the financial system as:

```text
balance = balance - payment
```

Use an auditable ledger.

Prefer double-entry accounting.

Example:

```text
Loan Disbursement

Debit:
Customer Loan Receivable

Credit:
Cash / Disbursement Account
```

Repayment:

```text
Debit:
Cash

Credit:
Principal
Interest Income
Fees
```

Verify:

* Immutable ledger entries
* Transaction IDs
* References
* Debit/credit balancing
* Reconciliation
* Reversals
* Adjustments
* Audit trail
* Idempotency
* Transaction timestamps

Every financial operation must be traceable.
